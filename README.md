# 大学课程 AI 自测与复习助手

## 1. 项目定位

本项目是一个面向本科生考试科目的 AI 自测与复习网页 Demo。

第一版不追求做成完整学习平台，而是先设计一套通用网页框架，再接入少量独立课程内容包，用低成本、短周期的方式验证学习闭环。

当前优先课程包：

- 电子科技大学：线性代数
- 上海交通大学数学系：高等代数

项目核心目标：

```text
帮助学生完成一次“知识点学习 -> 自测练习 -> 自动判分 -> 查看解析 -> 错题记录 -> AI 补练 -> 薄弱点反馈”的学习闭环。
```

第一版重点验证：

- 本校学生是否愿意使用该工具复习线性代数
- 学生是否能通过自测发现薄弱知识点
- AI 生成的补练题是否真的有帮助
- 知识点讲解、题目解析和错题反馈是否比单纯看 PPT 或刷题更方便
- 这个方向是否值得继续扩展

## 2. 当前阶段范围

第一版先做通用课程自测网页框架，不做大型多课程平台。

框架需要支持：

```text
课程包 -> 章节 -> 知识点 -> 自测题 -> 解析 -> 错题 -> AI 补练
```

建议初始范围：

```text
课程包：1 到 2 个
每个课程包章节：1 到 3 个
每个课程包知识点：5 到 10 个
题目数量：每个课程包 30 到 100 道人工审核题
试点学生：10 到 30 人
```

第一轮推荐：

1. 电科线性代数：作为完整闭环主测试课程包
2. 上交高等代数：先放少量样例知识点，验证多课程结构

电科线性代数第一章先按教材小节整理：

1. 1.1 矩阵及其运算
2. 1.2 高斯消元法与矩阵的初等变换
3. 1.3 逆矩阵
4. 1.4 分块矩阵

注意：上面四项是“第一章”下的四个小节，不是四个独立章节。网页中课程页显示“第一章 矩阵及其初等变换”，点入后再按 1.1 到 1.4 展示知识点。

高等代数可先选：

1. 多项式
2. 线性空间
3. 线性映射


## 5. 内容来源与边界

初期知识库可以参考：

- 各自学校对应课程教材
- 老师上课 PPT
- 课堂笔记
- 作业题
- 复习题或往年题，前提是合法获取和使用

建议使用方式：

```text
教材 = 知识体系基准
老师 PPT = 重点、讲法和考试倾向参考
课堂笔记 = 老师强调内容补充
作业题 = 练习题型参考
团队自己的总结 = 平台前台展示内容
```

注意：

- 不直接大段搬运教材原文
- 不公开展示老师 PPT 截图
- 不直接复制教材或课件内容作为平台内容
- 前台展示内容应尽量使用团队自己的总结和表达
- 如果后续扩大推广，应注意版权和授权问题

## 6. 内容生产流程

推荐流程：

```text
教材 / PPT / 笔记
-> AI 生成知识点总结初稿
-> 人工审核、改写和补充
-> 形成结构化知识点卡片
-> 配套人工题目和解析
-> 放入 Demo
```

核心原则：

```text
AI 负责提高整理效率，人工负责保证准确性。
```

AI 生成内容不能直接上线，尤其是线性代数中的定义、公式、条件、符号和计算步骤，必须人工审核。

## 7. 知识点卡片模板

每个知识点建议整理成固定格式：

```text
知识点名称：
所属课程包：
所属章节：
对应教材位置：
对应 PPT 位置：
一句话理解：
核心定义：
关键公式：
适用条件：
典型例题：
解题思路：
常见易错点：
考试常见题型：
适合生成的自测题类型：
人工审核状态：
```

示例：

```text
知识点名称：矩阵初等变换

所属章节：矩阵

一句话理解：
通过对矩阵的行或列进行基本变换，把矩阵化成更容易计算和分析的形式。

核心定义：
矩阵初等变换包括交换两行、某一行乘以非零常数、某一行加上另一行的倍数。

常见用途：
1. 求矩阵的秩
2. 求逆矩阵
3. 解线性方程组
4. 判断矩阵等价关系

常见易错点：
1. 行变换和列变换混用
2. 求逆矩阵时忘记同步变换单位矩阵
3. 混淆初等变换对秩和行列式的影响

人工审核状态：
待审核 / 已审核
```

## 9. 推荐技术路线

低成本推荐：

```text
Next.js + Tailwind CSS + 本地 JSON + localStorage + DeepSeek API
```

后续需要真实数据记录时再加入：

```text
Supabase
```

推荐开发顺序：

```text
1. 先用本地 JSON 做知识点和题目
2. 跑通知识点学习、自测、判分、解析流程
3. 用 localStorage 记录错题
4. 接入 DeepSeek API 生成补练题
5. 部署成网址给同学试用
6. 如果试点效果好，再接 Supabase 记录真实用户数据
```

第一版不要一开始就做复杂数据库、复杂登录、后台管理和多用户权限。

## 13. 风险与控制

### AI 答案不准确

控制方式：

- 核心题库必须人工审核
- AI 题目先作为补练题，不作为正式检测题
- 第一版优先生成选择题、判断题、简单填空题
- 对 AI 生成内容进行格式校验
- 增加“反馈错误”入口

### 学生只想抄答案

控制方式：

- 先展示提示，再展示完整解析
- 解析分步骤展开
- 错题需要二次作答
- AI 解题尽量采用引导式讲解

### 内容维护压力过大

控制方式：

- 第一版只做一门课
- 只覆盖 2 到 3 个章节
- 每个知识点先准备 5 到 10 道题
- AI 只做初稿，人工审核后使用

### 开发周期超出

控制方式：

- 暂缓老师端、班级管理、拍照搜题
- 登录使用邀请码和昵称
- 内容管理先用 JSON 或 Markdown
- 学习报告先用简单模板

### API 成本过高

控制方式：

- 固定题库练习不调用 AI
- 只在生成补练题和学习建议时调用 AI
- 缓存 AI 生成题目
- 限制每名学生每日生成次数

```text
3. 先用本地 JSON 存知识点和题目。
```

## 16. 高效 AI 协作 Skill

### Skill A：让 AI 生成初稿，不让 AI 直接定稿

适用场景：

- 知识点总结
- 题目生成
- 解析生成
- 学习建议

规则：

```text
AI 输出 = 草稿
人工审核 = 定稿
```

### Skill B：每次只让 AI 做一个小任务

错误方式：

```text
帮我完整开发整个平台。
```

推荐方式：

```text
请先帮我实现知识点列表页，数据来自 knowledge-points.json。
```

### Skill C：要求 AI 输出结构化结果

例如：

```text
请输出 JSON，字段包括 stem、type、options、answer、explanation、difficulty、tags。
```

### Skill D：让 AI 解释代码

推荐提示词：

```text
我是非计算机专业学生，请用初学者能理解的方式解释这段代码，每一部分负责什么。
```

### Skill E：让 AI 帮忙排查错误

推荐提示词：

```text
这是报错信息和相关代码。请先解释错误原因，再给出最小修改方案，不要重写无关代码。
```

## 17. 当前阶段制作原则

```text
学习闭环完整 > 功能数量多
解析质量高 > 题目数量多
贴合本校考试 > 做成通用平台
快速上线试用 > 技术架构复杂
低成本可维护 > 一开始追求高级架构
```

当前阶段不要追求“大而全”，而是先完成一个可以真实试用的小闭环。
